All fallback case IDs, reasons and retained resources are also listed in [competition_fallbacks.md](competition_fallbacks.md).

Validation checks exact columns, one row per requested ID, lexicographic row ordering, valid JSON, exact step fields, numbering, allowed phase/operation/state combinations, canonical step order, citation existence/cutoffs/resource state and normal finding/remediation/check consistency. Only ledger-listed fallback INCOMPLETE rows may omit findings/remediation or contain no steps; they can contain only uncited future verification checks for admissible resource anchors. This explicit exception is essential to avoid fabricating violations. It is format/evidence validation, not proof of canonical step completeness. The ordinary validator without a fallback ledger continues to reject these incomplete strict plans.

## Failures and improvements

Earlier provisional completions incorrectly treated retained/security or tombstone records as proof of deletion. Strict gates corrected this inference, explaining the earlier 29/32 to 23/32 status change. An explicit search-to-account source link improved exact rows from 8/32 to 9/32. Scope inference and validation were also fixed so unscoped SQL cannot prove absence and negative inventories cannot create opaque resource IDs. The competition-export change addresses mandatory coverage alone; it does not repair missing account ownership, late captures, anonymous 404s or unobserved restore permission. Primary account links remain unavailable in 342 applicable full investigations, including supported INCOMPLETE plans missing unidentifiable verification IDs. Some canonical checks cannot be proved from participant data; some extra checks are independently supported but omitted by public answers. No sample-specific mappings were added.
